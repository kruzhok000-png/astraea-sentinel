# Проверка Astraea Sentinel

Проверено локально 20 октября 2026 года, Windows / Node.js 24.19 / PostgreSQL 17.

## Выполнено

- `npm ci`: установка по lockfile успешна. В этой среде использовано зеркало npmmirror из-за недоступности основного registry.
- `npm run build`: генерация Prisma Client и строгая компиляция TypeScript успешны.
- Prisma schema validate: схема корректна.
- Все три миграции успешно применены к чистому настоящему PostgreSQL 17. Повторный `migrate deploy` не требует изменений.
- Seed выполнен дважды: в исходной гильдии осталось ровно три доверенных администратора, без дублей.
- Vitest с `RUN_DB_TESTS=1`: 23 из 23 тестов прошли, включая конкурентное создание черновиков, отправку, назначение проверяющего и одобрение на PostgreSQL.
- Native core: 9 тестов проверяют права, выдачу разрешённых ролей и служебные идентификаторы.
- Карточки сериализуются в пределах Discord embed/component limits на максимальных тестовых ответах. Проверены уточнение, включение апелляций, отсутствие повторной отправки и отключение действий завершённых заявок.
- HTML-превью построено из фактических embed-данных. На ширинах 390 и 1280 px нет горизонтального переполнения; дизайн просмотрен визуально. Это симуляция карточек, а не скриншот Discord.

Покрытие Vitest: 46,74% statements. Это не полное покрытие: реальный Discord API и доставка сообщений не проверялись end-to-end.

## Что необходимо проверить при первом запуске

Токен не использовался, бот не подключался к живому серверу. Docker-образ и инфраструктура BotHost локально не запускались.

1. Задать окружение по README, зарегистрировать slash-команды и настроить приватные каналы и роли.
2. Отправить тестовую заявку с отдельного аккаунта; сверить панель, приватную ветку, персональные данные и постоянное DM-досье.
3. Проверить закрытые DM: статус и включённая апелляция должны оставаться доступны через «Мой статус».
4. Пройти уточнение, паузу, переназначение, отказ с причиной и апелляцию. Проверить разграничение прав команды.
5. Одобрить тестовую заявку: только настроенные Member / game-роли, аудит решения и выдачи ролей.
6. Проверить ушедшего с сервера кандидата, недостаточную иерархию роли бота, временный отказ Discord и восстановление после перезапуска.
7. Сверить реальные карточки на мобильном и настольном Discord: итоговые шрифты, отступы и переносы определяет клиент Discord.

## Эксплуатационные ограничения

Использовать одну реплику. Discord и PostgreSQL не имеют общей транзакции: авария между отправкой нового сообщения и записью его ID может дать дубль сообщения. Задание восстановления повторяет незавершённую доставку и выдачу ролей. Перед масштабированием требуется распределённая очередь.

Следить за обновлениями зависимостей; срок поддержки Prisma 6 и ссылка на официальный график приведены в README. Этот отчёт не заменяет нагрузочный тест и независимый аудит безопасности.
