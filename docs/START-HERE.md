# Astraea: оформление и первый запуск

## Имя и описание

Имя бота: **Astraea Sentinel**. Никнейм на сервере: **Astraea · CELESTIAL**.

Описание для профиля приложения — скопируйте целиком:

```text
✦ Хранитель врат CELESTIAL. Помогаю подать заявку в гильдию, отслеживать рассмотрение и получать ответы команды. Начните с кнопки «Подать заявку» в канале набора.
```

Текст для закреплённого сообщения над панелью:

```text
✦ Твой путь в CELESTIAL начинается здесь.
Заполни анкету, расскажи о себе и дождись ответа команды. Черновик можно сохранить и закончить позже. Статус заявки — в личных сообщениях Astraea или по кнопке «Мой статус».
```

## 1. Оформить бота в Discord

Готовая аватарка: [astraea-avatar.png](branding/astraea-avatar.png). Загрузите изображение в исходном PNG.

Баннер: `docs/branding/astraea-banner.png`. Если в настройках профиля бота доступно поле Banner, загрузите его туда. Иконка приложения, аватар и баннер — разные поля; баннер не устанавливается загрузкой проекта на BotHost. Этот же файл можно использовать как обложку сообщения в канале набора.

Откройте [Discord Developer Portal](https://discord.com/developers/applications) и выберите приложение бота. Если его ещё нет, создайте приложение с именем Astraea Sentinel.

- В General Information загрузите иконку приложения и вставьте описание выше; сохраните изменения. Скопируйте Application ID — это будущий `CLIENT_ID`.
- В разделе Bot загрузите аватар бота, если он задаётся отдельно от иконки приложения, и укажите имя Astraea Sentinel. Сохраните изменения.
- В Bot включите Server Members Intent. Message Content Intent этому проекту не требуется.
- Получите токен в Bot и внесите его в защищённую переменную BotHost `DISCORD_TOKEN`.
- Через страницу установки / OAuth2 создайте приглашение со scopes `bot` и `applications.commands`. Выберите права из README и пригласите бота в CELESTIAL.

Аватар и описание задаются в настройках Discord. Загрузка картинки в папку проекта сама по себе профиль бота не изменяет. Названия пунктов панели могут отличаться в зависимости от языка интерфейса.

## 2. Что именно загружать на BotHost

Распакуйте ZIP. Внутри находится папка `astraea-sentinel`. **Корнем проекта на хостинге должно стать её содержимое**: рядом должны лежать `Dockerfile`, `package.json`, `package-lock.json`, папки `src` и `prisma`. Если хостинг сам распаковывает ZIP с внешней папкой, выберите `astraea-sentinel` как рабочую папку / корень сборки.

Загружайте весь проект из архива. `node_modules`, `dist`, локальные тестовые базы и `coverage` загружать не нужно: зависимости и сборка создаются на хостинге. В архиве этих папок нет. Аватар загружается отдельно в Discord; документация и изображения в `docs` работе бота не мешают.

## 3. Подготовить PostgreSQL и окружение

Создайте постоянную PostgreSQL-базу на хостинге или у провайдера БД. Сохраните её строку подключения. Обычная папка с файлами не заменяет PostgreSQL.

В переменных окружения сервиса бота задайте:

| Имя | Значение |
| --- | --- |
| `DISCORD_TOKEN` | Токен именно этого бота из Developer Portal |
| `CLIENT_ID` | Application ID этого приложения |
| `GUILD_ID` | `1389355523316519002` |
| `DATABASE_URL` | Строка подключения к постоянной PostgreSQL-базе |
| `LOG_LEVEL` | `info` |

Формат строки БД: `postgresql://USER:PASSWORD@HOST:5432/DATABASE?schema=public`. Реальные значения выдаёт провайдер; специальные символы логина и пароля должны быть URL-encoded. Настройки TLS берите у провайдера БД. `localhost` подходит только если БД действительно запущена в том же окружении; отдельный контейнер имеет собственное сетевое имя.

## 4. Собрать и запустить

Рекомендуемый вариант: выбрать сборку из **Dockerfile**, расположенного в корне проекта. Отдельную start-команду для него задавать не требуется: образ применяет миграции, создаёт начальные настройки и запускает бота. Используйте одну реплику и автоматический restart.

После успешной сборки в консоли **запущенного контейнера бота** выполните один раз:

```sh
node /opt/astraea/dist/src/deploy-commands.js
```

Это публикует slash-команды на сервере CELESTIAL. Команду повторяют после изменения списка slash-команд, а не при каждом запуске.

Если используете обычный Node.js runtime вместо Docker, выберите Node.js 22.12+ и запускайте из корня проекта:

```sh
npm ci
npm run build
npm run db:migrate
npm run db:seed
npm run deploy:commands
npm start
```

Для последующих запусков Node.js: `npm run db:migrate && npm run db:seed && npm start`. Подробности Docker Compose и особенности BotHost — в [README](../README.md).

## 5. Настроить сервер

Создайте каналы `#вступить-в-celestial` (публичный), `#заявки-команда` и `#аудит-заявок` (приватные). В двух приватных каналах запретите View Channel для @everyone, разрешите доступ боту и команде. Создайте роль Member и роли команды. Роль бота разместите выше Member и игровой роли.

Выполните настройку от одного из трёх первоначальных доверенных аккаунтов. Обычное право Discord Administrator само по себе не даёт внутреннего доступа к настройкам бота.

В поле ввода Discord выберите `/application-config`, затем заполните параметры через подсказки:

```text
panel: #вступить-в-celestial
moderation: #заявки-команда
audit: #аудит-заявок
member_role: @Member
curator_role: роль кураторов
moderator_role: роль модераторов
senior_role: роль старших модераторов
admin_role: роль администраторов заявок
deadline_hours: 72
cooldown_days: 14
appeals: True
```

Дополнительную игровую роль можно задать параметром `game_role`. Параметры можно сохранять несколькими вызовами команды. После настройки выполните `/application-panel channel: #вступить-в-celestial`.

## 6. Проверить первый запуск

Бот должен быть онлайн, slash-команды — видны на сервере. Пройдите анкету отдельным тестовым аккаунтом: проверьте DM-досье, карточку в приватном канале, ветку обсуждения, уточнение и одобрение с выдачей Member. Контрольные сценарии и границы выполненных тестов находятся в [QA.md](QA.md).

Если бот офлайн — смотрите ошибки запуска и подключение к БД. Если нет slash-команд — проверьте `CLIENT_ID`, `GUILD_ID` и результат deploy-commands. Если не выдаётся роль — проверьте Manage Roles и положение роли бота. При закрытых DM статус доступен через публичную панель.
